# 정리노트 (탭 + 탭별 다중 노트)

초보자 기준으로 바로 구현 가능한 **설계도 + 실행 코드**를 함께 제공합니다.

## 1. 목표
- 사용자가 탭(섹션)을 자유롭게 만든다.
- 각 탭 안에 노트를 여러 개 저장한다.
- 노트를 수정하면 자동 저장된다.

## 2. 설계도

### 2-1. DB 스키마(개념)
현재 코드는 브라우저 `localStorage`를 사용하지만, 나중에 DB로 옮길 때 동일한 구조를 권장합니다.

#### `tabs`
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | string(uuid) | 탭 고유 ID |
| name | string | 탭 이름 |
| created_at | datetime | 생성 시각 |
| updated_at | datetime | 수정 시각 |

#### `notes`
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | string(uuid) | 노트 고유 ID |
| tab_id | string(uuid) | 소속 탭 ID |
| title | string | 노트 제목 |
| content | text | 노트 내용 |
| created_at | datetime | 생성 시각 |
| updated_at | datetime | 수정 시각 |

관계: `tabs (1) : notes (N)`

---

### 2-2. API 명세(미래 백엔드 전환용)
브라우저 저장(localStorage)에서 서버 저장으로 바꿀 때 아래 API를 그대로 쓰면 됩니다.

- `GET /api/tabs` : 탭 목록 조회
- `POST /api/tabs` : 탭 생성
- `PATCH /api/tabs/:tabId` : 탭 이름 수정
- `DELETE /api/tabs/:tabId` : 탭 삭제

- `GET /api/tabs/:tabId/notes` : 특정 탭 노트 목록
- `POST /api/notes` : 노트 생성
- `PATCH /api/notes/:noteId` : 노트 수정
- `DELETE /api/notes/:noteId` : 노트 삭제

---

### 2-3. 화면 컴포넌트 설계
3-패널 구조로 분리합니다.

1. `TabSidebar`
   - 탭 목록 표시
   - 탭 생성/이름변경/삭제
2. `NoteListPanel`
   - 선택 탭의 노트 목록
   - 노트 생성/삭제
   - 최근 수정순 정렬
3. `NoteEditorPanel`
   - 제목 + 본문 편집
   - 1초 디바운스 자동 저장

### Android 비서앱 실행
Android 앱 표시명은 `정리노트`이며, `오늘` 화면을 중심으로 브리핑, 날씨 준비물, 핵심 일정, 음성 등록 진입점을 보여줍니다.

```bash
cd apps/android/capacitor
npm install
npm run sync
npm run open:android
```

릴리스 APK 빌드 검증은 JDK 21로 실행합니다. Windows PowerShell에서 Android Studio 내장 JDK를 쓰는 예시는 다음과 같습니다.

```powershell
cd apps/android/capacitor/android
$env:JAVA_HOME='C:\Program Files\Android\Android Studio\jbr'
$env:Path="$env:JAVA_HOME\bin;$env:Path"
.\gradlew.bat assembleRelease
```

빌드가 끝나면 release unsigned APK는 `apps/android/capacitor/android/app/build/outputs/apk/release/app-release-unsigned.apk`에 생성됩니다. 로컬 설치 테스트용 debug APK는 `apps/android/capacitor/android/app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다.

### Android Firebase 플러그인 브릿지 확인
Android 앱은 `www/capacitor.js`를 직접 번들하지 않고, Capacitor Android WebView가 시작할 때 주입하는 네이티브 브릿지를 사용합니다. `npm run sync`는 남아 있는 정적 `www/capacitor.js` 파일을 제거한 뒤 공유 모듈을 복사하므로, Firebase 플러그인 테스트 전 항상 다시 실행합니다.

테스트 방법:
1. `npm run sync` 실행 후 `android/app/src/main/assets/public/index.html`에 `capacitor.js` script 태그가 없는지 확인합니다.
2. `android/app/src/main/assets/capacitor.plugins.json`에 `FirebaseAuthentication`, `FirebaseFirestore`가 모두 있는지 확인합니다.
3. Android 기기에서 앱을 완전히 종료한 뒤 다시 열고 Google 로그인을 누릅니다.
4. 플러그인 초기화 오류가 뜨면 경고창의 `platform`, `nativePromise`, `plugins`, `headers`, `missing` 값을 함께 확인합니다. `missing=none`이어야 정상입니다.

Android Studio에서 실행한 뒤 다음을 확인합니다.

1. Google 로그인 후 `오늘`, `음성`, `노트`, `캘린더` 하단 탭이 보이는지 확인
2. `오늘` 화면에서 AI 브리핑 문서가 없을 때도 로컬 브리핑이 표시되는지 확인
3. `현재 위치로 날씨 브리핑 받기`를 눌렀을 때 위치 권한 요청이 뜨는지 확인
4. 위치 허용 후 현재 기온/체감/오늘 최고·최저/강수확률이 브리핑 문장에 표시되고, 우산·겉옷 같은 `챙길 것` 칩이 날씨에 맞게 바뀌는지 확인
5. 위치 권한 거부/날씨 실패 상태에서도 오늘 일정 목록과 음성 등록 버튼이 유지되는지 확인
6. `음성` 탭의 빠른 입력으로 할 일을 추가하면 `오늘` 화면과 웹 앱에 반영되는지 확인

모바일 날씨 브리핑은 별도 서버 없이 현재 위치를 얻은 뒤 Open-Meteo Forecast API(`https://api.open-meteo.com/v1/forecast`)를 직접 호출합니다. 응답은 `assistant_weather_forecast` localStorage 키에 30분 동안 캐시하며, 캐시가 오래되거나 현재 위치와 멀어지면 다시 받아옵니다. API 호출이 실패하면 저장된 날씨가 있으면 `저장된 날씨` 상태로 보여주고, 없으면 일정 기반 로컬 브리핑을 유지합니다.

AI 브리핑 서버가 준비되면 기존처럼 `users/{uid}/briefings/{YYYY-MM-DD}` 문서에 `headline`, `weatherSummary`, `carryItems`, `scheduleWarnings`, `topPriorities`, `suggestedOrder` 필드를 저장하면 앱이 우선 사용합니다. 또는 `users/{uid}/data/state.assistantBriefingEndpoint`에 HTTPS endpoint를 설정하면 앱이 현재 위치, 날씨, 일정 데이터를 POST로 보내 더 개인화된 브리핑을 받아옵니다.

### 스마트 플래너 사용
- 스케줄 탭 상단의 `스마트 플래너`는 `할 일 제안` 박스 하나로 노트 후보와 일정 재배치 제안을 함께 표시합니다.
- `업무 제안`은 Gemini API 키가 없으면 로컬 알고리즘으로 기한이 없거나 과중된 업무의 배정일을 제안합니다.
- Gemini API 키가 있으면 로컬 제안과 현재 노트 내용을 함께 보내 새 업무 후보와 일정 재배치 제안을 AI로 보강합니다.
- `적용하기`를 누르기 전까지 제안은 실제 업무/스케줄에 반영되지 않습니다.
- 노트 화면의 `노트에서 할 일 추출`은 AI 추출 결과를 바로 업무로 확정하지 않고 `할 일 제안` 박스에 표시되는 후보로 추가합니다.

## 5. 테스트 방법 (수동)

### A. 기본 동작 확인
1. 페이지 접속
2. `+ 탭` 클릭 → 탭 생성되는지 확인
3. 탭 클릭 시 해당 탭이 활성화되는지 확인
4. 탭을 더블클릭했을 때 탭 칸 안에서 이름이 바로 수정 가능한지 확인(Enter 저장 / Esc 취소)
5. 탭 액션에 색상/삭제 아이콘만 노출되는지 확인
6. `+ 노트` 클릭 → 현재 탭에 노트가 생성되는지 확인
7. 페이지 구역 이름을 더블클릭해 수정하고, 구역 우측 `+`를 눌러 해당 구역 안에 페이지가 추가되는지 확인
8. `Ctrl/Cmd + 클릭` 또는 `Shift + 클릭`으로 페이지 여러 개를 선택한 뒤 다른 구역이나 `구역 밖`으로 드래그하면 함께 이동하는지 확인
9. 브라우저 배율을 80% 정도로 낮췄을 때 노트 본문 줄 배경이 편집 패널 오른쪽 끝까지 자연스럽게 채워지는지 확인
10. 우측 `업무 목록`을 접었을 때 텍스트 없이 가운데 화살표 버튼만 표시되고, 클릭하면 다시 펼쳐지는지 확인
11. 데스크톱 폭에서 노트 목록/편집기, 편집기/업무 목록 사이에 마우스를 올리면 좌우 화살표 커서로 바뀌고 넓은 범위로 폭이 조절되는지 확인

### A-1. UI 사용성 확인
1. 로컬 실행은 `python3 -m http.server 4173`으로 시작하고 `http://localhost:4173`에서 확인합니다.
2. 상단 앱 이름이 `정리노트`로 표시되고, 데스크톱 폭에서 상단바, 섹션 탭, 서식 툴바가 한 줄 흐름으로 보이며 검색창 포커스 시 레이아웃이 흔들리지 않는지 확인합니다.
3. 섹션 탭이 단추형이 아니라 노트 인덱스처럼 색상 탭으로 붙어 보이고, 활성 섹션의 색상 바가 자연스럽게 이어지는지 확인합니다.
4. 에디터 제목/본문 폭이 과하게 넓지 않고 긴 본문을 입력해도 줄 간격과 노트지 배경이 읽기 좋은지 확인합니다.
5. 노트 목록의 활성 페이지, 빈 상태 안내, 삭제/색상 아이콘 hover 상태가 구분되는지 확인합니다.
6. 우측 업무 목록을 접었을 때 빈 흰 패널이 남지 않고, 펼치기 손잡이만 보이며 노트 본문 폭이 자연스럽게 넓어지는지 확인합니다.
7. 업무 카드의 체크박스, 기한/난이도 배지, 편집/삭제 아이콘이 서로 겹치지 않고 클릭 가능한지 확인합니다.
8. 스케줄 주간/월간 달력의 날짜 셀이 넓게 벌어지지 않고 1px 그리드처럼 촘촘하게 이어지는지 확인합니다.
9. 모바일 폭에서 상단바가 두 줄로 정리되고 노트 목록, 에디터, 스케줄 화면이 세로로 자연스럽게 쌓이는지 확인합니다.

### B. 자동 저장 확인
1. 노트 제목/내용 입력
2. 1초 정도 입력 멈춤
3. 편집기 우측 상단 상태가 `저장 중...` → `저장됨`으로 바뀌는지 확인

### C. 영속화(localStorage) 확인
1. 노트 내용 수정 후 브라우저 새로고침
2. 수정 내용이 유지되는지 확인

### D. 삭제 보호 확인
1. 탭이 1개만 남았을 때 삭제 시도
2. 삭제가 막히고 안내 문구가 뜨는지 확인

### E. 로그인 경고 확인 (로컬 작업 보호)
1. 로그인하지 않은 상태에서 탭/노트를 생성하거나 내용 입력
2. 우측 상단 `Google 로그인` 클릭
3. `로그인 시 클라우드 데이터가 로컬 데이터를 덮어쓸 수 있어요` 경고창이 뜨는지 확인
4. `취소`를 누르면 로그인 흐름이 중단되는지 확인
5. 팝업이 막히는 브라우저에서는 리다이렉트 로그인으로 자동 전환되는지 확인

### F. GitHub Pages 로그인 확인 (Firebase)
1. `Google 로그인` 클릭 시 팝업이 즉시 닫히며 실패하면 브라우저 알림 메시지를 확인
2. 안내대로 Firebase Console > Authentication > Settings > Authorized domains에 `sangkyoung92-cmyk.github.io`가 등록되어 있는지 확인
3. 등록 후 다시 로그인 시 정상적으로 계정 선택/로그인이 되는지 확인
4. 로그인 후 우측 상단 사용자 정보 옆 `로그아웃` 버튼이 보이고, 클릭 시 로그아웃되는지 확인

### G. 할 일 기능 확인
1. 우측 `할 일` 패널에서 `+ 할 일` 클릭 후 항목 생성
2. 할 일 추가 모달에 `프로젝트` 입력 항목이 없는지 확인
3. 스케줄 캘린더에 오늘/이번 주/이번 달 날짜로 업무를 배정했을 때 `오늘 할 일 / 이번 주 할 일 / 이번 달 할 일` 섹션에 각각 표시되는지 확인
4. 각 섹션 헤더의 화살표(▾/▸) 버튼으로 목록 접기/펼치기가 동작하는지 확인
5. 체크박스를 클릭해 완료/미완료 상태가 반영되는지 확인
6. 할 일 텍스트를 클릭했을 때는 완료 상태가 바뀌지 않고, 체크박스 클릭에서만 완료 상태가 바뀌는지 확인
7. 마감기한 없이 할 일을 추가하면 스케줄에 마지막으로 등록된 할 일의 날짜를 자동으로 가져오는지 확인
8. 하나의 할 일을 오늘/이번 주/이번 달 날짜에 각각 배정하면 세 섹션에 중복 노출되는지 확인
9. 오늘 섹션에서 체크했을 때 오늘 배정분만 완료되고, 같은 할 일의 주/월 배정분은 유지되는지 확인
10. 노트 본문에서 텍스트를 선택 후 `Ctrl/Cmd + Q`를 눌러 할 일이 추가되는지 확인
11. `노트에서 할 일 추출` 버튼으로 현재 노트 내용이 할 일 목록에 추가되는지 확인

### H. 스케줄 기능 확인
1. 스케줄 탭에서 업무를 날짜에 드롭해 배정되는지 확인
2. 스케줄 사이드바 업무 목록도 `오늘/이번 주/이번 달/기타` 섹션으로 표시되고, 화살표로 접기/펼치기가 동작하는지 확인
3. 하나의 업무가 여러 기간에 배정되어 있으면 `오늘/이번 주/이번 달` 섹션에 중복 표시되는지 확인
4. 사이드바에서 `오늘/이번 주/이번 달` 중 한 섹션의 체크박스를 클릭했을 때 해당 섹션 범위 일정만 완료되는지 확인
5. 업무가 오늘 날짜 칸에 배정되어 있으면 `오늘 할 일` 섹션에 표시되는지 확인 (기한과 무관)
6. 월간 뷰에서도 각 일정 칩의 체크박스로 완료/미완료가 반영되는지 확인
7. 배정된 일정 칩을 드래그해 다른 날짜로 이동되는지 확인
8. `Ctrl`(Mac은 `Cmd`)를 누른 채 드래그하면 원본은 유지되고 복사 배정되는지 확인
9. 일정 칩/업무 카드의 휴지통 아이콘으로 삭제되는지 확인
10. `AI 일정 추가` 클릭 시 일정이 자동 추가되고, 설정의 `AI 일정 추가 시 참조 내용` 저장값이 반영되는지 확인
11. 새 할 일을 생성할 때 `기한`을 지정하면 스케줄 탭 해당 날짜에 자동 배정되는지 확인
12. 스케줄 탭(주/월 뷰)에서 날짜 칸을 더블클릭하면 업무 추가 모달이 열리고, 선택한 날짜가 기본 기한으로 채워지는지 확인
13. 스케줄 업무 추가 모달에도 `프로젝트` 입력 항목이 없는지 확인
14. 스케줄 업무 목록에서 이름이 긴 항목이 한 줄 말줄임표(`...`)로 표시되어 레이아웃이 깨지지 않는지 확인
15. 스케줄 업무 카드의 `수정` 버튼(연필 아이콘)을 누르면 기존 값이 채워진 모달이 열리는지 확인
16. 수정 모달에서 업무명/난이도/기한을 바꾸면 즉시 반영되고, 기한을 비우면 배정된 날짜가 제거되는지 확인
17. 스케줄 주간 뷰의 주 시작이 일요일인지 확인
18. 주말(토/일) 날짜가 파란 계열로, 공휴일이 빨간 계열로 표시되는지 확인
19. 월간 뷰에서 모든 날짜 셀의 높이가 동일하고 셀 간 간격 없이 붙어서 표시되는지 확인
20. 오늘 날짜(예: 2026-04-13)가 월요일이면 월간 헤더에서도 `월` 열에 표시되는지 확인
21. 월간 뷰에서 날짜 셀에 업무가 많을 때 `+n개` 배지가 셀의 맨 하단에 고정되어 보이는지 확인
22. 월간 상태에서 `주간` 탭을 누르면 항상 오늘(현재 날짜)이 포함된 주로 이동해 표시되는지 확인
23. 데스크톱 폭에서 업무 목록과 캘린더 사이에 마우스를 올리면 좌우 화살표 커서로 바뀌고 드래그로 업무 목록 폭이 조절되는지 확인

### I. 스마트 플래너 기능 확인
1. 스케줄 탭 상단에 `할 일 제안` 박스와 `업무 제안`, `적용하기`, `접기` 버튼만 표시되는지 확인
2. Gemini API 키가 없는 상태에서 `업무 제안`을 누르면 로컬 기준 제안이 표시되고, 캘린더에는 아직 저장되지 않는지 확인
3. 기한이 없거나 이번 주에 몰린 업무가 `구분 / 업무이름 / 적용일자(기한) / 난이도 -> 제안 사유` 형식으로 표시되는지 확인
4. Gemini API 키가 있는 상태에서 `업무 제안`을 누르면 버튼 문구가 `AI 제안 중...`으로 바뀌고, 완료 후 로컬/AI 제안이 같은 박스에 표시되는지 확인
5. 현재 노트에 업무성 문장을 작성한 뒤 `업무 제안`을 눌렀을 때 새 업무 후보가 같은 박스에 표시되는지 확인
6. 노트 화면의 `노트에서 할 일 추출`로 만든 후보도 `할 일 제안` 박스에 표시되는지 확인
7. `적용하기`를 누른 뒤에만 제안된 업무 생성/일정 이동이 캘린더에 반영되는지 확인
8. `접기/펼치기` 버튼이 `할 일 제안` 박스를 접고 펼치는지 확인

## 9. 노트 녹음/AI 요약
- 노트 탭의 `녹음` 버튼은 브라우저 음성 인식(Web Speech API)을 사용해 마이크 음성을 현재 페이지의 녹음 버퍼에 저장합니다. 녹음 중에는 파형, 경과 시간, 정지 버튼이 있는 녹음 패널이 표시되며, 받아쓴 원문은 노트 본문에 자동 입력되지 않습니다.
- `정지`를 누르면 `녹음한 내용을 현재 노트에 추가할까요?` 확인창이 뜹니다. `AI 요약하여 추가하기`를 체크하면 녹음 버퍼만 요약해서 노트 하단에 추가하고, 체크하지 않으면 녹음 원문을 `발화자 A: 내용` 형식으로 노트 맨 아래에 추가합니다.
- 브라우저가 말소리를 감지하지 못해 `no-speech`를 반환하면 팝업을 띄우지 않고 저장 상태 영역에만 안내합니다.
- 추가가 끝난 녹음 버퍼는 비워집니다. 다시 녹음하면 새 녹음 내용으로 처리합니다.
- 설정 > AI 설정에서 `AI 요약 프롬프트`를 수정/저장하거나 기본값으로 되돌릴 수 있습니다. 응답 형식 같은 고정 지시문은 앱 내부 기본 규칙으로 처리합니다.
- 현재 구현은 오디오 파일을 저장하지 않고 음성 인식 결과 텍스트만 저장합니다. 긴 녹음도 대체로 텍스트 용량만 늘어나므로 저장 부담은 작지만, 실제 음성 파일까지 저장하도록 바꾸면 분당 수백 KB에서 수 MB 단위로 커질 수 있습니다.

### 로컬 실행 방법
```bash
python3 -m http.server 4173
```

브라우저에서 `http://localhost:4173` 접속 후 설정에서 Gemini API 키를 저장합니다. 녹음 기능은 Chrome/Edge 계열 브라우저와 마이크 권한이 필요합니다.

### 테스트 방법
1. 새 노트를 선택하고 `녹음`을 눌러 마이크 권한을 허용한 뒤 파형/경과 시간/정지 버튼이 표시되고 말한 내용이 본문에 바로 추가되지 않는지 확인합니다.
2. 녹음 패널의 `정지`를 눌러 녹음 추가 확인창이 뜨는지 확인합니다.
3. `AI 요약하여 추가하기`를 체크하지 않고 `예`를 눌러 `발화자 A: 내용` 형식의 원문이 노트 맨 아래에 추가되는지 확인합니다.
4. 다시 녹음한 뒤 `AI 요약하여 추가하기`를 체크하고 `예`를 눌러 녹음 내용 요약만 노트 하단에 추가되는지 확인합니다.
5. 설정 > AI 설정에서 요약 프롬프트에 응답 형식 지시문이 노출되지 않는지, 저장 후 다시 열었을 때 값이 유지되는지 확인합니다.
6. Gemini API가 503을 반환하면 원본 오류 JSON 대신 서버 혼잡 안내가 표시되는지 확인합니다.

### 녹음 안정성 메모
- 녹음 중 브라우저가 `no-speech`를 반환해도 녹음 세션을 자동 재시작합니다.
- 녹음 내용은 정지/추가 시점에 선택된 노트가 아니라 녹음을 시작했던 노트에 추가됩니다.

### Android Google login troubleshooting

로그인 버튼이 반응 없이 오래 기다린 뒤 `Firebase native plugins are not ready` 진단을 띄우는 경우:

1. `cd apps/android/capacitor && npm run sync`를 실행해 Android assets에 최신 `www`를 복사합니다.
2. Android Studio에서 앱을 완전히 삭제하거나 강제 종료한 뒤 다시 설치/실행합니다.
3. Google 로그인 버튼을 누르면 즉시 `Google login...` 상태가 보여야 하며, Auth 브릿지가 아직 준비되지 않은 경우 최대 12초 대기 후 진단 메시지가 표시됩니다.
4. 로그인은 `FirebaseAuthentication`만 먼저 확인하고, 로그인 후 클라우드 데이터 로딩 시 `FirebaseFirestore`를 확인합니다.
5. `Android Firebase login is not ready yet`은 보통 Firebase 콘솔 설정 문제가 아니라 앱의 Capacitor 네이티브 브릿지/플러그인 준비 문제입니다. 최신 APK를 재설치해도 계속되면 alert의 `platform`, `nativePromise`, `plugins`, `headers`, `missing` 값을 확인합니다.
6. Google 계정 선택 후 실패하거나 `ApiException: 10`/`DEVELOPER_ERROR`가 뜨는 경우에는 Firebase Console의 Android 앱에 설치 APK 서명 인증서 SHA-1/SHA-256을 추가하고 `google-services.json`을 갱신해야 합니다.
7. `missing=FirebaseAuthentication`이고 `plugins`/`headers`에 `FirebaseAuthentication`이 없으면 Android `variables.gradle`에 `rgcfaIncludeGoogle = true`가 필요합니다. 이 값이 없으면 Google 로그인 SDK가 런타임 APK에 포함되지 않아 Auth 플러그인이 등록되지 않을 수 있습니다.
8. `headers=FirebaseAuthentication`인데도 `unable to find plugin`이 계속 뜨면 이전 APK가 남아 있을 가능성이 높으므로 앱을 삭제한 뒤 새 APK를 다시 설치합니다.
